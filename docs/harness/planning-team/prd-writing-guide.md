# PRD 작성 가이드 — 서비스 트라이앵글과 스코프 트레이드오프

이 문서는 기획팀 `service-planner`가 PRD(제품 요구사항 문서)에 들어갈 컨셉/BM 판단을 만들 때, 그리고 `planning-writer`가 그 브리프를 PRD로 옮길 때 참조하는 판단 기준이다. **어떤 서비스를 만들지(도메인, 타겟, 구체적 기능 목록)는 다루지 않는다** — 그건 프로젝트마다 다른 `docs/planning/service-concept.md`(프로젝트별 산출물)의 몫이다. 이 문서는 오직 "PRD를 쓸 때 어떤 논리 구조와 판단 기준을 지켜야 하는가"만 다룬다.

## 서비스 트라이앵글

타겟 사용자(누구를 위한 것인가) → 핵심 가치(어떤 문제를 푸는가) → 기능(그 가치를 어떻게 구현하는가)이 논리적으로 이어지는지 항상 확인한다. 기능 우선순위는 비즈니스 모델적 사고(핵심 가치·핵심 리소스·범위)로 근거를 댄다 — 유행이라서, 그냥 넣고 싶어서가 아니라.

## 스코프 트레이드오프 명시

기능을 넣을지 말지 판단할 때 "이번 프로젝트 범위에서 이게 맞는 단순화인가"를 항상 트레이드오프로 명문화한다(예: "본인 확인 = 최소 정보만 확인 후 진행" 같은 결정은 보안 수준 vs 구현 범위의 트레이드오프를 명시하는 방식으로 남긴다).

## 레퍼런스 서비스 해석

사용자가 참고 서비스를 언급하면 그대로 베끼지 않고, 이 프로젝트의 성격(타겟, 핵심 평가/성공 기준)에 맞게 종합해서 반영한다 — 왜 그 요소를 채택/배제했는지 근거를 남긴다.

## 비목표(Out-of-scope) 감별

새 기능 요청이 PRD 비목표와 부딪히면, "왜 부딪히는지 + 포함하면 어떤 트레이드오프가 생기는지"까지 분석해서 브리프에 담는다. 최종 포함 여부는 사용자 결정이지만, 그 판단에 필요한 자료를 만드는 게 이 역할이다.

## 문서 간 논리 충돌 탐지

브리프를 만들 때 관련 문서(특히 PRD의 AC/비목표)를 실제로 다시 읽고, 지금 만들려는 기능/화면의 설계와 논리적으로 모순되는 조항이 없는지 확인한다. 발견하면 어느 쪽이 맞는지 스스로 결론짓지 않고, 트레이드오프와 함께 보고해 사용자 결정을 받는다 — 결정이 나면 그 결정을 반영해 충돌하는 원본 문서 쪽도 함께 갱신되도록 한다(한쪽만 고치고 다른 쪽을 그대로 두지 않는다).

## PRD 구조

목표 / 비목표(N-항목) / 타겟 사용자 / 핵심 가치 / 유스케이스(UC-xx) / 요구사항(FR-xx 또는 PR-xx) / 인수 기준(AC-xx). 사용자 여정 전체 흐름은 Mermaid flowchart로 보완한다.

## 유스케이스(UC-xx)로 사용자 흐름을 목록화한다

요구사항(FR/PR)이 "무엇을 할 수 있어야 하는가"의 단위라면, 유스케이스는 "누가, 어떤 트리거로, 어떤 흐름을 시작하는가"의 단위다 — 둘은 다른 축이라 하나가 있다고 다른 하나를 생략하지 않는다.

1. **전체 목록 표**: ID(UC-xx) / 유스케이스명 / 액터 / 트리거 — 이 프로젝트에서 있을 수 있는 사용자 흐름을 빠짐없이 나열한다.
2. **상세화는 선별한다**: 전체를 다 상세화하지 않는다 — 대표 정상 흐름 1개 + 이번 과제/스코프의 대표 엣지 케이스 1개 정도만 골라, 단계별 표(정상 단계 + 예외 단계 "4a, 5a..." 형식)로 상세를 남긴다. 무엇을 대표로 골랐는지와 왜 그게 대표인지(어떤 사고력·리스크를 드러내는 케이스인지)를 한 문단으로 설명한다.
3. UC-xx는 화면정의서의 SCR-xxx, 기능정의서의 FR-xx와 상호 참조 가능해야 한다 — 최종 매핑 표(어느 문서에 둘지는 프로젝트 재량)에서 세 ID 체계가 서로 연결되는지 확인한다.

## 체크리스트

- [ ] 타겟 사용자 → 핵심 가치 → 기능이 한 문장으로 설명 가능한가?
- [ ] 새 기능/스코프 결정마다 트레이드오프가 명문화됐는가?
- [ ] 비목표와 충돌하는 요청을 침묵 없이 분석해 보고했는가?
- [ ] 관련 문서(AC/비목표)를 다시 읽고 논리 충돌 여부를 확인했는가?
- [ ] 사용자 여정이 Mermaid flowchart로 표현됐는가?
- [ ] 유스케이스 전체 목록 표가 있고, 대표 케이스(정상+엣지) 1~2개가 단계별로 상세화됐는가?
- [ ] UC-xx가 SCR-xxx·FR-xx와 상호 참조되는가?
