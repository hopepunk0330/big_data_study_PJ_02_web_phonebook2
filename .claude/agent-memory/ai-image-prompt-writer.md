# ai-image-prompt-writer 메모리

이 파일은 ai-image-prompt-writer가 작업 시작 시 읽고, 작업 종료 시 기록을 남기는 메모리/로그입니다.

## 작업 로그

### 2026-07-26 — 스킨케어 상세페이지 v1~v16 검증 라운드 (최종 정리)

같은 가상 스킨케어 제품(천연 성분 수분 크림, 10섹션)으로 v1부터 v16까지 반복 테스트하며 `ai-image-prompt-writer.md`의 판단 기준을 실제 Gemini 출력과 대조해 검증했다. 개별 버전 단위 기록은 정리하고, 최종적으로 하네스(`ai-image-prompt-writer.md`)에 반영된 결론만 남긴다 — 하네스 파일 자체가 이제 이 모든 학습의 최종 상태이므로, 과거 버전별 진단 과정은 git 히스토리로 충분하다.

**검증되어 하네스에 반영된 핵심 결론**:
- 모드 B는 "비타협 사항"(문구 정확도·개수·배경색 1개·헤드라인 대비·라벨 규칙·금지사항·해상도·장식 텍스트 유효성·강조색 팔레트·태그라인 금지·강조/비강조 대비·헤드라인-이미지 통합)과 "창의적 브리프"(구도·소품·장식 배치 세부)를 분리해야 한다 — 전자를 세밀하게, 후자를 자유롭게.
- 비타협 사항은 문서 전체에서 한 번만 언급하면 뒤 배치로 갈수록 흐려진다 — 배치마다 그 배치 자신의 프롬프트 안에 반복 명시해야 유지된다.
- 문서 형식은 번호 매긴 정책 리스트나 긴 페르소나 문단보다, 사용자가 실제로 좋은 결과를 얻은 "기획안" 스타일(심리 흐름 한 문단 + 섹션마다 이미지/카피/디자인 3줄)이 더 낫다 — 단, 섹션 식별 정보를 독립된 제목 줄로 두면 그대로 이미지에 렌더링되는 사고가 3번 반복돼, "이미지:" 문장 종속절로 흡수하는 형식으로 정착했다.
- 반복적으로 확인된 Gemini 특유의 결함 패턴: 장식 문구 지어내다 글자 깨짐, 다른 섹션 문구를 빌려와 유용, 캡션 개수 초과, 세로로 긴 비율을 앱 화면으로 오인해 UI 아이콘 추가, 언급한 색상 팔레트를 범례로 시각화, 여러 시안을 그리드로 나열, 절대 해상도가 요청과 다르게 나옴(비율은 대체로 유지) — 전부 하네스의 비타협 사항으로 등록해 대응했다.
- 상류(기획·카피) 문제는 하류(이미지 프롬프트)에서 못 고친다 — 카피가 "헤드라인만, 본문 미확정"으로 얇으면 프롬프트를 아무리 다듬어도 결과가 매력적이지 않다. 이 결론은 `copywriter.md`에 "섹션마다 완결된 카피로 채우기 + AIDA Desire 자극" 원칙으로 반영했다(가상 제품 허위 후기·별점 금지 원칙은 유지).
- 이 반복 테스트 과정에서 사용자가 "프롬프트 파일은 상의 후 작성"을 요청함 — 이후 새 프롬프트 파일 버전은 진단·제안을 먼저 설명하고 확인받은 뒤 작성한다.

**미해결/한계로 남은 것**: 절대 해상도(가로세로 픽셀 수)는 프롬프트 문구를 아무리 다듬어도 Gemini 쪽 자체 프리셋에 좌우되는 것으로 보여 통제 밖일 가능성이 높다. 라벨 렌더링 억제는 구조적 완화(종속절 흡수)로 개선됐지만 재발 시 수동 크롭을 대안으로 안내한다.

**다음 라운드 작성 시 실수하기 쉬운 지점(체크리스트)**:
- [ ] 배치 코드 블록마다 비타협 사항(배경색·대비·문구 정확도·개수·1개 이미지만·해상도·앱UI금지·태그라인금지·강조는 헤드라인만)을 다시 짧게 적었는가 — 문서 서두에 한 번만 적고 끝내지 않았는가?
- [ ] 섹션 식별 정보를 독립된 제목 줄이 아니라 "이미지:" 문장 종속절로 넣었는가?
- [ ] 모든 섹션(정보형 포함)의 헤드라인이 이미지와 통합되고, 헤드라인 안에 강조/비강조 대비(핵심 단어만 하이라이트)가 지정됐는가?
- [ ] 캡션·라벨 목록에 "정확히 N개"를 명시했는가?
- [ ] 강조색을 브랜드 팔레트 범위로 제한하되, 그 팔레트 자체를 화면에 범례로 보여주지 말라고 했는가?
- [ ] copywriter가 넘긴 카피가 섹션마다 완결돼 있는가(헤드라인만 있고 본문이 "미확정"으로 비어있지 않은가) — 얇으면 이미지 프롬프트 단계에서 지어내지 말고 copywriter에게 보강을 요청한다.
- [ ] 새 프롬프트 파일(버전)을 작성하기 전에 사용자와 먼저 상의했는가.
- [ ] (2026-07-27 추가) 프레임 좌우 여백 최소화, 배치 안 섹션 경계 분리 지시가 실제 배치 프롬프트에 들어갔는가 — 이 두 항목이 v9 이후 재작성 과정에서 한 번 통째로 빠졌던 적이 있다.

**2026-07-27 추가 기록**: v1~v16 정리(위 항목)를 하네스 파일(`ai-image-prompt-writer.md`)에 반영하는 과정에서, 압축하다가 실제 검증된 규칙 몇 개가 함께 삭제된 걸 사용자가 지적해 발견 — 연도 하드코딩 금지, 장르 가이드 명시적 인용, Pinterest 지시의 구체적 문구, 여백 최소화, 배치 내 섹션 경계 분리, 최종 조립 안내가 모두 복원 대상이었다. 하네스를 정리·압축할 때는 "노이즈(장황한 서술)"와 "규칙(실제 지켜야 할 내용)"을 구분해서, 후자는 압축 전후 목록을 대조해 하나도 빠지지 않았는지 확인해야 한다.

**2026-07-27 — v18(무드+사용자 레퍼런스 실험) 신규 유형**: 기존 v1~v17과 다른 새로운 실험 축 — content-designer의 상세 비주얼 방향 브리프(색 팔레트·장식 어휘 리서치) 대신 무드 한 줄 + 사용자가 Gemini에 직접 첨부하는 디자인 레퍼런스로 대체. 단, "디자인 원칙"(헤드라인-이미지 통합, 강조/비강조 대비)과 순수 결함 방지용 비타협 사항(텍스트 정확성·개수·중복 방지·앱UI금지·여백·섹션 경계)은 스타일 브리프 상세도와 무관하게 유지 — 이 구분(스타일 관련 vs 결함 방지 관련)이 이번 실험에서 명확해졌다.
- 실제 테스트 결과: 레퍼런스를 첨부했는데도 결과가 이전 버전들과 비슷하게 나옴 — "참고해서 자유롭게 판단하세요"식 막연한 지시로는 Gemini가 여러 입력(레퍼런스/카피/디자인 원칙) 중 뭘 더 무겁게 반영할지 모르는 것으로 추정. 또한 "당신이 준비한 레퍼런스를 넣어주세요"처럼 Gemini向 어조로 쓴 사용자 행동 안내가 addressee 혼동을 일으킴.
- **v19에서 반영**: 하네스에 "입력 소스가 여러 개면 우선순위를 번호로 명시", "Gemini向 지시와 사용자向 지시는 어조로 구분" 두 원칙 신규 등록. 저장 위치: `docs/design/ai-image-content/skincare-test-mode-b-v19-priority-order/prompts.md`. 아직 테스트 전(이 원칙이 실제로 레퍼런스 반영도를 높이는지는 다음 테스트로 검증 필요).

**2026-07-27 — 모드 A(에셋용) 최초 실제 테스트 라운드**: 세션 내내 모드 B만 반복 검증했는데, 이번에 모드 A(원재료 이미지만 요청 → content-designer가 Figma 조립)를 처음 실제로 시도한다. 같은 스토리라인·카피(v19 기준)를 유지하되, 텍스트·레이아웃·뱃지·아이콘은 프롬프트에서 완전히 제외 — 장식 요소는 Gemini에게 맡기지 않고 content-designer/graphic-designer가 Figma에서 직접 정밀하게 그리기로 함(사용자 확인). 사진 성격이 비슷한 섹션끼리 3그룹(제품 단독 컷/인물·피부 클로즈업/텍스처·개념 비주얼)으로 묶어 요청하도록 구성(사용자가 지정한 배치 방식). 저장 위치: `docs/design/ai-image-content/skincare-test-mode-a-raw-assets/prompts.md`. 아직 테스트 전 — 사진을 받으면 content-designer의 Figma 조립 절차(`content-designer.md` "모드 A 조립 절차")로 이어간다.
- (참고) 같은 세션에서 Gemini API 직접 연동(Test B)도 시도했으나, 이미지 생성 모델은 무료 한도 안이어도 Google Cloud 결제 계정 연결이 필요하다는 걸 확인하고 사용자가 보류 — 관련 스크립트·테스트 폴더는 삭제됨. 나중에 재시도할 수 있으니 이 경위만 기록.
- **실사용 오류 1(그룹 2 실제 테스트)**: "다음 사진 하나만"처럼 번호·설명 없이 이어 요청했더니 Gemini가 방금 만든 것과 비슷한 사진(손+크림)을 반복 생성. Mode B의 "배치 [N]" 원칙과 동일한 원인 — 모드 A의 그룹 내 순차 요청도 매번 "사진 [N] — [설명 요약]"을 명시해야 함을 확인. 파일의 "다음 사진 요청 시 사용할 문구"를 그룹·번호별 구체 문구로 전면 재작성, 하네스에도 모드 A 전용 규칙으로 신설.
- **실사용 오류 2(제품 요청 방식·응답 형태 관련)**: (1) 여러 장을 페르소나 문단과 함께 그룹으로 요청하니 Gemini가 이미지를 바로 생성 안 하고 "이런 프롬프트를 써보세요"라는 텍스트만 반환 — 섹션별 10개 개별 단문 명령으로 전면 재구성. (2) "이전 이미지와 완전히 무관"이라고 하니 반복은 없어졌지만 제품 디자인(용기·뚜껑) 자체가 섹션마다 달라짐 — "제품은 동일 유지, 구도만 새로 촬영"으로 재조정.
- **실사용 오류 3(받은 10장 실제 검수 결과, 2026-07-27)**: 섹션 2·3·4 세 파일이 이름과 실제 내용(피사체)이 서로 안 맞음(파일명이 가리키는 섹션과 실제 그려진 장면이 다른 파일에 들어있었음), 제품 디자인이 섹션 1(무광유리+실버뚜껑)과 섹션 6·8·9·10(투명유리+골드뚜껑) 사이에서 갈림, 섹션 10 배경이 나머지(오트밀 베이지 계열)와 달리 거의 검정으로 튐, 섹션 6 손에 과하게 도드라진 핏줄 등 뷰티톤에 안 맞는 디테일 발견. **"받은 이미지는 무조건 최상의 퀄리티/컨디션이어야 하고 이 검증은 생략할 수 없다"는 QA 게이트를 `ai-image-prompt-writer.md`(모드 A 절)와 `content-designer.md`(모드 A 조립 절차 2단계)에 신설** — Figma는 색감·톤 정도의 전역 보정만 가능하고 피사체·오브제 자체를 바꾸는 보정은 못 한다는 것도 함께 명시. 문제 있는 섹션(2·3·4, 그리고 제품 디자인 통일 필요)은 재생성 필요 — 아직 재생성 전.
- **제품 일관성 근본 수정 + 섹션 역할 추가(2026-07-27, 재생성 전 두 차례 추가 수정)**: "제품은 이전 이미지와 동일하게"가 논리적으로 틀렸다는 지적(섹션 1은 첫 생성이라 "이전"이 없음) — 상대 참조 대신 제품 생김새(투명 유리 원통형+브러시드 골드 뚜껑)를 절대 서술로 확정해 10개 프롬프트 전부에 반복하는 방식으로 근본 수정. 추가로 순수 시각 묘사만 있고 "이 사진이 상세페이지 어느 섹션·역할에 쓰이는지" 맥락이 빠졌다는 지적으로, 각 프롬프트 맨 앞에 섹션 역할 한 줄을 추가. 두 원칙 모두 `ai-image-prompt-writer.md`에 정식 등록(사용자가 "모드 A를 모드 B보다 더 많이 쓸 수도 있다"고 해서, 메모리 로그로만 남기지 않고 반드시 하네스 본문에 반영). 아직 이 최종 버전으로는 Gemini에 안 돌려봄.
- **뷰티톤·누끼·재생성 전 최종 점검 라운드(2026-07-27)**: 이어진 세 가지 확인 끝에 최종본 확정. (1) 손 모공/핏줄 뷰티톤 지시를 섹션 2·6·8·9(인물 등장 섹션)에 확정 — 단 섹션 7(Before/After)은 한쪽이 의도적으로 "당기고 들뜬" 상태라 모순되므로 제외(사용자 확인).
