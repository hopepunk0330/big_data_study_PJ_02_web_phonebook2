# design-prompter 메모리

이 파일은 design-prompter가 작업 시작 시 읽고, 작업 종료 시 기록을 남기는 메모리/로그입니다.

## 작업 로그

### 2026-08-25 — brand-designer 브리프(단독): mercari 정식 Brand Guide 문서 작성 — 확정 디자인 7개 화면(`126:2601` 하위) 근거, "새 Brand Guide 작성 안 함" 유보 취소
- **원본 요청**: design-pl이 이전 라운드의 실측 결과(색상/타이포/보더·radius·그림자/간격 전부 이미 확보)를 그대로 전달하며, "정식 Brand Guide 문서는 안 만든다"던 이전 유보를 사용자 확인("브랜드 컨셉서도 정리하는 거 맞지?")으로 취소하고 brand-designer에게 정식화를 지시. design-concept-round 스킬 3단계 (A)-1번 / house rule 2-3번에 해당.
- **핵심 판단**: (1) 이미 확보된 실측값은 재관찰 없이 그대로 신뢰하고 문서화에만 쓰도록 명시 — 단, 아이콘/모티프는 스펙(크기/색상/스트로크 두께/용도)이 비어 있어 이 부분만 `get_design_context`로 재확인하도록 범위를 좁혀 지시. (2) 문서 구조는 fig-file-organization.md 2-3번(색상→타이포→보더/radius→그림자→간격→장식 모티프, 구조적 수치+컨셉 성격 표현 장치 둘 다) 순서를 그대로 따르게 함. (3) 문서 저장 위치는 이 레포에 이미 있는 기존 브랜드 문서들이 전부 별도 프로젝트(contacts 앱, fileKey `zgGlMBwFglaDlaeyP4CkgR`) 소유임을 직접 확인해 명시하고, mercari 전용 신규 경로(`docs/design/mercari/`)가 필요함을 인지시킴. (4) Concept A/B는 별개 톤이 아니라 하나의 통합 시스템(상태/시나리오 차이만)이라는 점을 문서 구조에도 명시적으로 강제. (5) 확정 화면 7개 절대 무수정, 지어내지 않기(모든 값 실측 근거) 재확인.
- **구체화 포인트**: 완료 기준에 문서 실제 생성/경로 보고, 6개 섹션 전부 포함 확인, 아이콘 재확인 결과의 구체성, 확정 화면 무수정 확인, A/B 통합 서술 확인을 명시.

### 2026-08-25 — design-qa 브리프(단독): mercari 확정 화면 7개 + 신규/보강 컴포넌트 7종 + 스펙 시트 종합 감사 — 이번 라운드 마지막 단계
- **원본 요청**: design-pl이 확정 화면 7개(`126:2601` 하위)와 design-systems가 이번 라운드에 추출·보강한 컴포넌트(Price Input/Progress Row/Product Row/Badge류/Choice Card 개명/Hero Price Card 재확인/CTA 재확인·통합)에 대한 종합 감사를 지시. 점검 기준 5개(대비/네이밍/바인딩/원본 대조/아이콘 조립), B_03 보더 누락 예외 재검증, 스펙 시트 완성도 확인이 명시적 요구사항.
- **핵심 판단**: (1) `docs/design/mercari/brand-guide.md`(8차 brand-designer 문서)를 직접 읽고 표로 옮겨 컴포넌트별 정확한 대조값(radius/padding/색/폰트)을 브리프에 그대로 박아넣어, design-qa가 재해석 없이 바로 대조 가능하게 함. (2) 다크 히어로 대비 미달은 "원본 고정값이라 지적은 하되 치명 등급 강하게 매기지 않음, 기존 지적과 중복이면 통합"으로 심각도 완화 지침을 명시해 design-systems의 기존 보고와 이중 집계되지 않게 함. (3) 이 프로젝트는 2px 그리드가 확정 스타일이라 `token-architecture-guide.md`의 8pt 그리드 일반 원칙과 충돌한다는 점을 명시해 오탐(false positive) 방지. (4) 그림자 완전 부재·Eyebrow 배경 `visible:false` 의도된 비가시 상태 두 가지를 별도 항목으로 강조(치명 판단 기준 포함). (5) icon-craft-guide/motion-timing-guide는 이번 라운드 무관이라 명시적으로 범위 제외. (6) B_03 예외는 design-qa가 새로 판단하지 않고 "이미 처리됐다는 보고가 사실인지"만 2가지 조건으로 재검증하도록 범위를 좁힘.
- **구체화 포인트**: 완료 기준에 5개 기준별 발견사항(이상 없음도 명시), 심각도+nodeId, B_03 재검증 결과, 스펙 시트 완성도(개별 컴포넌트별)를 명시. `❌ 미채택 —` 라벨은 스팟 확인만(내용 결함 지적 금지) 재확인.

### 2026-08-25 — brand-designer 브리프(단독): mercari Brand Guide "Figma 페이지"로 시각화 — 정본은 `docs/design/mercari/brand-guide.md`, 재실측 금지
- **원본 요청**: 지난 라운드 brand-designer가 Brand Guide를 마크다운 문서로만 작성하고 `figma-file-organization.md` 1번 관례(brand-designer 전용 "Brand Guide" Figma 페이지에 시각 프레임으로 구현)를 빠뜨림 — 사용자가 "Figma에서 안 보인다"고 직접 지적. design-pl이 이미 작성된 md 문서 전문(6개 섹션 값 전부 확정)을 그대로 전달하며 "새로 관찰하지 말고 시각화만 하라"고 지시.
- **핵심 판단**: (1) 이 라운드는 신규 컨셉 결정이 아니라 이미 정본(source of truth)인 문서의 시각화이므로 시안 3개 게이트 없음(PL이 명시적으로 언급 안 함 = 게이트 아님, 임의로 부과하지 않음). (2) `docs/design/confirmed/` 확정 스펙 문서 작성 대상도 아님 — md 문서 자체가 이미 그 역할을 하고 있어 별도 문서를 새로 만들지 않음. (3) "표를 텍스트로 옮겨 적지 않는다"를 명확히 해 실제 렌더링된 스와치/샘플/도형 요소로만 구현하도록 강제(색상 박스, 실제 폰트 크기 샘플, radius 적용된 도형, 2px 그리드 눈금 등). (4) 두 가지 확정화면 불일치/특이사항(Eyebrow 배경 비가시 의도, B_03 보더 누락)은 고치지 않고 페이지 안에 주석으로만 남기도록 위치까지 지정. (5) 로컬 md 파일은 이 프로젝트(JY_Harness) 소유라 읽기 가능하지만 재실측 없이 값 자체는 바꾸지 않음, mercari 프로젝트 폴더(로컬)는 이번 작업과 무관해 손댈 필요 자체가 없음을 재확인. (6) 확정 화면(`126:2601` 하위 7개) 절대 무수정 재확인 — 이번 작업은 열어볼 필요조차 없음.
- **구체화 포인트**: 페이지 배치(레퍼런스 다음, "{작업명} Concepts"와 같은 구역), 프레임 네이밍 관례, 섹션별 구체적 craft 기준(스와치+라벨 쌍, 폰트 위계별 실제 렌더링, radius 도형 예시, 그림자 없음의 의도 명시, 2px 그리드 눈금 시각화, 라인/컬러 아이콘 이중 체계 설명), `use_figma` 다회 호출(섹션별 순차 진행) 지시, 완료 기준(페이지 node id, 섹션별 구성 요소, 주석 위치)을 구체화.

### 2026-08-25 — graphic-designer + design-systems 브리프(순차): mercari 결함 수정 라운드 — 아이콘 정식 컴포넌트화(3종) → 변수 컬렉션 신설 + 7종 컴포넌트 바인딩 + 스펙 시트 3종 + 인스턴스 교체(HIGH 4/MEDIUM 2 해소)
- **원본 요청**: design-pl이 지난 컴포넌트 추출 라운드에서 design-qa가 발견한 HIGH 4건/MEDIUM 2건(아이콘 raw FRAME 방치, 변수 컬렉션 부재로 하드코딩 색상, 신규 컴포넌트 4종 미교체, Choice Card/Hero Price Card/CTA 스펙 시트 누락 등)을 전달하며, graphic-designer(아이콘 원화 정리)를 먼저, design-systems(변수+컴포넌트화+스펙시트+인스턴스 교체)를 그다음 순차로 실행할 두 브리프를 요청. 라우팅은 PL이 이미 확정.
- **핵심 판단**: (1) `docs/design/mercari/brand-guide.md`(정본 겸 확정 스펙 문서, 2-4번 선례 상속 케이스)의 1절 색상표·6절 아이콘 스펙을 그대로 인용해 두 워커가 재해석 없이 바로 쓸 수 있게 함. (2) `icon-craft-guide.md`의 Basic/Visual 트랙 판정을 graphic-designer가 3개 아이콘 각각에 직접 적용하도록 위임(브랜드 가이드의 "라인/면 혼합/면" 서술과 트랙 판정은 다른 축이라 임의로 미리 단정하지 않음). (3) 이번 라운드는 "이미 확정된 컴포넌트/화면의 개별 결함 수정"이라 3-B번 4-1번 게이트(전체 확장 승인) 대상이 아님을 확인(2-4번 마지막 문장 근거) — 시안 3개 게이트도 미적용, 두 브리프 모두 명시하지 않음. (4) 인스턴스 교체 작업은 확정 화면(절대 무수정 원본)에 대한 예외적 승인된 수정이라는 점과, 교체 전후 시각적 동일성 스크린샷 검증을 필수 조건으로 명시. (5) White Sheet 텍스트 3계열 대비 이슈는 별도 트랙(사용자 확인 필요)이라 이번 라운드 절대 건드리지 않게 별도 절로 격리. (6) `figma-generate-library` 무거운 4단계 절차 대신 최소 변수 컬렉션 신설로 범위를 좁혀 과잉 구현 방지(Simplicity First). (7) `figma-page-format-guide.md`의 스펙 시트 포맷(제목→설명→variant 그리드→여백, clipsContent=false)을 기존 4종 스펙 시트에서 그대로 clone하도록 명시.
- **구체화 포인트**: 두 브리프 모두 목표/범위/참고자료/완료기준 명시. graphic-designer 브리프는 "형태 재창작 금지, 순수 정리·구조화만" 경계를 명확히 함. design-systems 브리프는 과제 A~E 순서 고정, scope 명시(ALL_SCOPES 금지), Ink 뮤트 opacity는 변수화하지 않고 레이어 속성 유지(가장 단순한 방식 채택) 지시. 순서(graphic-designer 먼저 → design-systems)는 Figma 동시 접근 충돌 방지 차원에서도 재확인. 이 라운드 종료 후 house rule상 design-qa 재검증이 여전히 필요하다는 점을 design-pl에게 별도 안내(라우팅 결정은 아님, 정보 제공).
