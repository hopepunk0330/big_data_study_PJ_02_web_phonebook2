이번 라운드 대상: @$ARGUMENTS

이 스킬은 `content-designer`·`ai-image-prompt-writer`(디자인팀), `service-planner`·`copywriter`(기획팀)를 어떤 순서로 부르고, 어디서 사용자 확인을 거치고, 실제 생성 결과가 나쁠 때 어떻게 재조정하는지를 실행 절차로 풀어놓은 것이다. 각 에이전트 정의 파일(`.claude/agents/*.md`)의 판단 기준이 정본이고, 이 스킬은 그걸 어떤 순서로 적용할지의 절차 체크리스트일 뿐이다.

**실행 주체와 승인 경계**: design-pl이 `Agent` 도구로 디자인팀 워커(content-designer, ai-image-prompt-writer)를 직접 호출한다. 기획팀(service-planner, copywriter)은 design-pl이 직접 부르지 않는다 — 필요성을 메인 세션에 보고하고, 메인 세션이 기획팀(planning-pl 경유)에 요청하는 기존 팀 간 조율 경로를 따른다(`.claude/agents/content-designer.md` 참고). 모드 선택·배치 크기 같은 사용자 확인이 필요한 지점에 도달하면 design-pl은 그 즉시 멈추고 메인 세션에 반환한다 — 메인 세션이 사용자에게 실제로 묻고 답을 받은 뒤 **"[메인 세션 확인] 사용자 답변: ..."** 형식으로 다시 호출할 때만 다음 단계로 진행한다.

## 0단계 — 산출물 종류·대상 시장 확인

무엇을 만드는지(상세페이지/카드뉴스/기타)와 어느 시장(국가/플랫폼)을 대상으로 하는지 먼저 확인한다 — 이게 이후 리서치 방향을 결정한다. 한국 시장 대상 상세페이지·카드뉴스면 1단계에서 `korean-ecommerce-detail-page-guide.md`가 1차 근거가 된다는 걸 미리 인지한다. 애매하면 메인 세션에 확인을 요청한다.

## 1단계 — 기획팀 입력 확보 (스토리라인 + 카피)

- 스토리라인(섹션/슬라이드 구성, 몇 개로 나눌지)이 아직 없으면 메인 세션에 `service-planner` 브리프가 필요하다고 보고한다.
- 카피(섹션별 헤드라인/본문/CTA)가 아직 없으면 같은 방식으로 `copywriter` 브리프가 필요하다고 보고한다.
- 이 둘은 design-pl 산하가 아니라서(기획팀 소속) design-pl이 직접 호출하지 않는다 — 메인 세션이 받아와서 design-pl에 다시 전달할 때까지 대기한다.

## 2단계 — content-designer 비주얼 방향 (장르 리서치)

`content-designer`를 호출해 비주얼 방향 브리프를 받는다. 이 단계는 design-pl이 같은 팀 워커로 직접 호출 가능하다(메인 세션 경유 불필요). content-designer의 판단 기준(`.claude/agents/content-designer.md` 참고)에 따라:
- "업종 브랜드 트렌드"가 아니라 "실제 쓰일 장르·시장의 관습"을 리서치 대상으로 삼는다.
- 타이포그래피는 스펙시트가 아니라 그래픽 역할·의도로 서술한다.
- **배경색은 후보 나열이 아니라 주 배경색 1개(또는 톤이 매우 가까운 2개)로 확정한다** — 실제로 후보를 나열해서 넘겼다가 섹션마다 색이 바뀌어 나온 사고가 있었다(2026-07-26).

## 3단계 — ai-image-prompt-writer 모드 선택 게이트

`ai-image-prompt-writer`를 호출하기 전, design-pl이 직접 부를 수 있다(같은 팀). ai-image-prompt-writer는 스토리라인·카피·비주얼 방향을 받아 모드 A(에셋용, 이후 content-designer가 Figma로 조립)와 모드 B(완성형, Gemini가 최종 결과물을 통째로 생성) 중 근거 있는 추천을 만들어 반환하고 멈춘다. 메인 세션이 사용자에게 묻고 **"[메인 세션 확인] 사용자 답변: 모드 A/B"** 형식으로 확인받은 뒤에만 다음 단계로 진행한다.

## 4단계 — 배치 크기 결정 (트레이드오프 설명 필수)

모드 B로 확정되면, ai-image-prompt-writer가 배치 크기(한 번의 Gemini 요청에 섹션 몇 개를 담을지)를 정한다. **기본값은 배치당 2섹션이다** — 실제 테스트에서 배치당 4섹션은 텍스트 중복·글자 깨짐·해상도 저하를 냈고, 2섹션은 안정적이었다(2026-07-26 확인). 배치를 키우면 요청 횟수는 줄지만 텍스트 오류 위험이 커진다는 트레이드오프를, 특별한 요청이 없어도 메인 세션 보고에 한 줄로 명시한다 — 사용자가 명시적으로 "요청 횟수를 더 줄여달라"고 하면 배치를 키우되 이 위험을 다시 알린다.

## 5단계 — 최종 프롬프트 파일 생성

ai-image-prompt-writer가 파일을 작성한다. 저장 위치는 `docs/design/ai-image-content/{작업명 슬러그}/prompts.md`(새 작업마다 새 슬러그 폴더, 기존 폴더 덮어쓰지 않음). 파일에는 다음이 반드시 포함된다:
- 심리 흐름을 반영한 짧은 소개 문단(기획안 스타일) — 긴 페르소나 문단은 필수가 아니다(실제 비교로 페르소나 없는 쪽이 더 나았음, `ai-image-prompt-writer.md` 참고). 연도는 하드코딩하지 않는다.
- 배치 단위 생성 안내 + 다음 배치 요청 시 사용할 정확한 문구 템플릿 + 완료 선언 지시
- **"이 배치 안의 각 섹션 문구를 정확히 1번씩만 렌더링하고 중복 렌더링하지 말 것"** 명시
- 실제 렌더링될 문구는 정확히, 표현 방식(구도·타이포 그래픽 역할)은 의도 중심으로

## 6단계 — 사용자 테스트 + 문제 발견 시 재조정 루프

사용자가 실제로 Gemini에 붙여넣어 결과를 확인한다. 문제가 나오면 아래 표대로 원인을 지목하고 해당 단계로 되돌아간다 — 무작정 전체를 다시 만들지 않는다.

| 증상 | 가능한 원인 | 되돌아갈 단계 |
|---|---|---|
| 텍스트 중복/글자 깨짐 | 배치가 너무 큼(텍스트량 과다) | 4단계(배치 축소) |
| 색상이 섹션마다 다름 | 배경색이 후보 나열로 남아있음 | 2단계(주 배경색 재확정) |
| 결과가 밋밋하고 뻔함 | 타이포/구도가 스펙시트처럼 막연하게 쓰임 | 5단계(그래픽 역할 서술로 재작성) |
| 장르가 안 맞음(예: 서구 미니멀이 나옴) | 리서치가 일반 브랜드 트렌드로 샜음 | 2단계(장르·시장 재확인, 가이드 재참조) |
| Gemini가 그리드/콜라주로 요약함 | "다음 배치" 요청 문구가 모호했음 | 5단계 템플릿 그대로 재요청 |

## 7단계 — 최종 조립 안내

Gemini에서 받은 배치 이미지들을 실제로 다운로드해 세로로 이어 붙이는 최종 조립은 이 스킬 밖에서 진행된다(Gemini 안에서 자동으로 합쳐지지 않는다). 모드 B는 다운로드 후 사람이 직접 이어 붙이면 끝이다. **모드 A는 content-designer가 Figma에서 실제로 조립하는 별도 작업 라운드다** — 구체적 절차(이미지 업로드, 카피 얹기, 장식 요소 배치, 정밀 스펙 원칙)는 `.claude/agents/content-designer.md`의 "할 일" 절 "모드 A 조립 절차"를 그대로 따른다(이 스킬은 그 절차를 요약 재기술하지 않는다 — 에이전트 정의 파일이 정본이다). **여러 컨셉(시안)을 처음 정하는 라운드라면, 조립을 시작하기 전에 반드시 `figma-file-organization.md` 2-1-C번의 1차(brand-designer가 페르소나 3개 정의 + 대표 섹션 1개만 데모)→2차(확정된 페르소나 하나로 전체 섹션 레이아웃 시안) 2단계 게이트를 거친다(2026-08-19 신설, harness-auditor 70차 지적)** — 이 게이트 없이 3개 컨셉을 한 번에 전체 섹션까지 만들어버린 사고가 실제로 있었다. 상세 기준은 `.claude/agents/design-pl.md`·`content-designer.md`를 따른다. 조립 완료 여부와 무관하게, 여기까지가 이 스킬의 범위다.
